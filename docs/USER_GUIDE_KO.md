# Aruba MM Cleanup 사용자 가이드

## 목적

`show global-user-table list role profiling` 조회 결과에서 사용자 MAC을 수집하고, 대상 snapshot을 미리 보여 준 뒤 운영자가 `DELETE N`으로 승인한 경우에만 `aaa user delete mac <mac>`을 실행합니다.

## 첫 연결과 삭제 승인

1. 처음 접속한 주소의 SSH 서버 키는 SHA-256 지문과 함께 표시됩니다. 장비 관리자에게 별도 경로로 지문을 확인한 뒤 승인하십시오.
2. 이후 같은 키는 앱 전용 known_hosts에서 확인합니다. 저장된 키가 바뀌면 자동으로 연결을 차단하므로 원인을 먼저 확인해야 합니다.
3. 앱은 `no paging`과 MM/Mobility Conductor/WLC 신원을 확인한 뒤 Role을 조회합니다.
4. 조회된 모든 대상 MAC을 확인하고 `DELETE <대상 수>`를 정확히 입력해야 삭제가 시작됩니다.
5. 주기 실행도 매 회 새 snapshot을 다시 보여 주고 승인을 요구합니다. 승인하지 않은 회차는 삭제하지 않습니다.

## 화면 구성

- `MM IP/Host`: 접속할 Aruba MM 주소입니다.
- `계정`, `암호`: SSH 접속 계정입니다.
- `Enable 암호`: enable 단계가 필요한 환경에서만 입력합니다.
- `Role`: 기본값은 `profiling`입니다.
- `장비 응답 대기(초)`: SSH 접속, 인증, 명령 응답을 기다리는 시간입니다.
- `주기(초)`: 자동 반복 실행 간격입니다. 최소 1초이며 입력한 값이 그대로 적용됩니다.
- `작업 상태`: 조회/삭제 처리 상태와 주기 실행 대기 시간을 `다음 실행`으로 표시합니다.
- `이번 삭제 취소`: 다음 MAC 삭제 전 이번 실행의 남은 삭제를 취소합니다.
- `이력 전체 지우기`: 화면에 남아 있는 최근 삭제 이력을 지웁니다.
- `세션 연결 해제`: 현재 유지 중인 MM 세션을 수동으로 종료합니다.

## 결과 확인

대시보드는 앱을 켠 이후 아래 수치를 누적 표시합니다.

- 누적 조회 MAC: 조회에서 발견한 중복 제거 삭제 대상 MAC의 작업 건수 누계
- 누적 삭제 완료: 삭제 후 검증 조회에서 사라진 MAC의 작업 건수 누계
- 작업 상태: 조회/삭제 처리와 다음 주기 실행 대기를 한 곳에서 표시

삭제 실패, 확인 필요, 남은 MAC, 재조회 상태는 `삭제 대상 및 결과` 테이블과 최근 삭제 이력에서 확인합니다.
조회 결과의 `Type` 값이 `N/A`인 MAC은 자동 삭제를 계속 진행하지만, 결과 테이블과 로그에 `Type=N/A: 관리자 직접 장비 지정 필요` 안내가 남습니다.
`삭제 대상 및 결과`와 `최근 삭제 이력`의 `MAC` 셀을 클릭하면 해당 MAC이 클립보드에 복사되고 중앙 팝업이 1초 동안 표시됩니다.

실행 요약은 결과 폴더의 `cleanup_summary.json`에 저장됩니다. raw 장비 출력은 저장하지 않습니다.
parser가 각 row를 삭제 대상으로 선택하거나 제외한 reason은 audit JSON에 함께 저장됩니다.
결과 폴더 권한 문제 등으로 실행 요약 저장에 실패하면 화면 결과는 유지하고 warning 로그만 남깁니다.
GUI는 snapshot 승인 직후 삭제를 시작합니다. CLI는 승인 후 `--delay`만큼 추가 대기할 수 있습니다.
장비 응답 대기 시간은 GUI의 `장비 응답 대기(초)` 또는 CLI의 `--timeout`으로 조절합니다.
최근 삭제 이력은 장시간 주기 실행 중 UI가 무거워지지 않도록 최근 500개 행만 유지합니다.
최근 삭제 이력은 결과 폴더의 `deletion_history.jsonl`에 저장되고 프로그램 재시작 시 복원됩니다.
로그창은 최근 1000줄만 유지합니다.
`재조회됨`으로 표시된 MAC은 장비 상태 확인이 필요합니다. 프로그램은 같은 MAC에 삭제 명령을 자동으로 다시 보내지 않습니다.

## 세션 동작

- GUI는 프로그램이 켜져 있는 동안 같은 MM 접속 정보를 재사용합니다.
- 수동 1회 실행과 주기 실행 모두 같은 세션으로 조회, 삭제, 삭제 후 검증 조회를 처리합니다.
- 주기 실행이 다음 실행을 기다리는 중에도 수동 1회 실행은 시작할 수 없습니다.
- 접속 정보가 바뀌면 기존 세션을 닫고 새로 접속합니다.
- 프로그램을 완전히 종료하거나 `세션 연결 해제`를 누르면 세션을 닫습니다.
- 실행 중 프로그램을 종료해도 Tk 화면은 네트워크 timeout이나 runner lock을 기다리지 않고 닫히며, 세션 정리는 백그라운드에서 진행됩니다.
- 장시간 유휴 상태로 세션이 끊긴 경우 명령 실패 시 한 번 재접속하고 같은 명령을 재시도합니다.
- 재접속할 때도 SSH 서버 키, 페이징, 장비 신원 게이트를 다시 통과합니다.
- 단, `aaa user delete mac <mac>` 삭제 명령은 응답 실패 시 재시도하지 않고 `확인 필요` 상태로 기록합니다.
- `이번 삭제 취소`와 `주기 실행 정지`는 다음 MAC 삭제 전과 삭제 후 검증 조회 전에 반영됩니다.
- CLI는 한 번 실행할 때만 세션을 사용하고 실행 종료 시 연결을 닫습니다.

## Web UI와 CLI

- Web UI는 항상 `127.0.0.1`에만 열립니다. 외부 공개용 reverse proxy나 원격 서버 용도로 사용하지 마십시오.
- Web UI는 장비 조회 후 별도 확인 화면을 표시하며, 승인 직전에 fresh query snapshot이 바뀌면 삭제를 취소합니다.
- CLI에는 `--password`나 `--enable-password` 옵션이 없습니다. 암호는 화면에 표시하지 않는 안전 입력으로 받습니다.

## 운영 주의

이 도구는 실제 사용자 세션을 삭제합니다. 처음 사용할 때는 운영 영향이 없는 시간대에 수동 1회 실행으로 조회 결과와 작업 상태/삭제 취소 동작을 먼저 확인하세요.

같은 MAC이 여러 줄에서 발견되어도 정규화된 MAC 기준으로 `aaa user delete mac <mac>` 명령은 한 번만 실행합니다.
